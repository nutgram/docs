Nutgram 5 is out! This release brings dependency injection to class-based commands, lets you control how often your bot reports file transfer progress, and makes it easier to test what your bot sends to Telegram.

<!-- truncate -->

## Commands with dependency injection

Register command classes with `onCommand()` and let Nutgram's container resolve their dependencies. Implement `Command` to declare a description, with support for a default description and translations. Implement `WithScopes` to choose where Telegram lists the command, such as in private chats only. When you publish the command list, `registerMyCommands()` now returns a list of the registered commands with their languages and scopes.

Handler patterns also accept PHP backed enums. You can pass enum cases directly to methods such as `onCommand()`, `onText()`, and `onCallbackQueryData()` to reuse the same values when building buttons and handling their callbacks. [Handler documentation](/docs/usage/handlers)

## File uploads and downloads

`withProgress()` now gives uploads and downloads the same `Progress` object. The callback can read the transferred bytes, total bytes, percentage, and transfer type. Built-in triggers let you run the callback at intervals based on bytes, percentage points, or elapsed time. You can also implement `Trigger` to define your own rule.

For a large upload, `EverySecond(2)` limits progress reports to one every two seconds.

```php
use SergiX44\Nutgram\Support\Progress\Progress;
use SergiX44\Nutgram\Support\Progress\Triggers\EverySecond;
use SergiX44\Nutgram\Telegram\Types\Internal\InputFile;

$bot
    ->withProgress(function (Progress $progress): void {
        echo $progress->percentage() . "%\n";
    }, new EverySecond(2))
    ->sendVideo(video: InputFile::make('video.mp4'), chat_id: $chatId);
```

If your bot generates a report or a CSV in memory, `InputFile::makeFromString()` turns that content into an upload. `InputFile` also accepts PSR-7 streams. [File transfer documentation](/docs/usage/sending_requests)

## Simpler server-side conversations

When you start a conversation from a scheduled job or another server-side task, pass the user and chat IDs to `Conversation::begin()`. Nutgram uses them as context, so the first step can call `sendMessage()` and let Nutgram infer the destination. You can also pass an optional `threadId` to target a topic. [Conversation documentation](/docs/usage/conversations)

## Assert on requests and responses

`assertRaw()` now passes `RequestData` and `ResponseData` to your callback. Use them to check request parameters, headers, and uploaded files alongside the response payload or API error. The callback can return a boolean or run testing-framework assertions directly with a `void` return type. [Testing documentation](/docs/testing/asserting#assertraw)

## Upgrading an existing bot

Nutgram 5 requires **PHP 8.4 or newer**. If you use `registerCommand()`, move those registrations to `onCommand()`. Instantiate Telegram types with `new` where you previously used `::make()`. Check code that depends on `getChat()` returning a `Chat`, since it now returns `ChatFullInfo`. [Full list of changes on GitHub](https://github.com/nutgram/nutgram/pull/796)
